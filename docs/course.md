# প্রিমিয়াম কোর্স এরিয়া

ল্যান্ডিং পেজে আর অ্যাপের কোর্স কার্ডে ৳৪৯০-এর মাসিক কোর্স বিক্রি হচ্ছে অনেক দিন,
আর তার ফিচার-তালিকায় শুরু থেকেই লেখা আছে দুটো কথা — **"প্রতিটি সেশনের রেকর্ডেড
ভিডিও"** আর **"প্রতিটি সেশনের আলাদা নোট"**। কোডে এতদিন এর কিছুই ছিল না; সদস্য পেতেন
শুধু তিনটে টেলিগ্রাম লিংক। এই ফিচারটা সেই প্রতিশ্রুতির বাকি অর্ধেক।

সদস্য এখন হোম স্ক্রিনে "আমার কোর্স" তাকটা দেখেন, সেখান থেকে কোর্স খোলেন, সেশনের
তালিকা পান, একটা সেশনে ঢুকে **ভিডিও** দেখেন, **নোট** পড়েন, **নোট নামান**, আর
**সেই ক্লাসের মতামত** দেন। কোথায় থেমেছিলেন সেটাও মনে থাকে, এক ডিভাইস থেকে আরেকটায়।

## কোর্স মানে কী

একটা কোর্স = একটা পরিচয় (`id`) + কার জন্য খুলবে (`membership` বা `product`) +
ক্রমানুসারে সাজানো সেশনের তালিকা।

| কোর্স | কী দিয়ে খোলে | কোথায় লেখা |
|---|---|---|
| `course-live` | `memberships['live-class'].until > now` | `course_data/catalog.json` |

আজ একটাই কোর্স, কিন্তু `catalog.json` একটা অ্যারে — নতুন কোর্স যোগ করা মানে
আরেকটা অবজেক্ট লেখা, কোড ছোঁয়া নয়।

দুই রকম অ্যাক্সেস আগে থেকেই সাইটে আছে, আর `/api/course` দুটোই দেখে:

- **`memberships`** — মেয়াদসহ, অ্যাডমিন ছাড়া কেউ লিখতে পারে না (`firestore.rules`)।
- **`courses[]`** — আজীবন আনলক, বইয়ের মতো।

> ⚠ **এককালীন বিক্রির কোর্স যোগ করার আগে পড়ুন।** `firestore.rules` ইচ্ছাকৃতভাবে
> ব্যবহারকারীকে নিজের `courses[]`-এ লিখতে দেয় — TrxID দেওয়ার সাথে সাথে বই খুলে
> যাওয়ার জন্য। ৳১০০-র বইয়ে সেটা মেনে নেওয়া যায়, ভিডিও কোর্সে যায় না: কনসোল
> জানা একজন ছাত্র নিজেই নিজেকে কোর্স দিয়ে দিতে পারবেন। তাই `product` দিয়ে কোনো
> কোর্স বিক্রি করার আগে অ্যাডমিন-ছাড়া-লেখা-যায়-না এমন একটা আলাদা ফিল্ড
> (`courseGrants`) বানিয়ে `firestore.rules`-এ সেটাকে `memberships`-এর পাশে বসাতে
> হবে। আজকের `course-live` মেম্বারশিপে চলে বলে এই ফাঁকটা তাকে ছোঁয় না।

## দুটো ফাইল, দুটো নিয়ম

```
course_data/catalog.json     ট্র্যাকড     শিরোনাম, ব্রিফ, সময়, ক্লাসের তালিকা
course_data/private.json     gitignored  ভিডিও ID + নোট ফাইলের ম্যাপ
course_notes/<course-id>/    gitignored  নোটের আসল বাইট (lNN.html + lNN.pdf)
```

`catalog.json` ইচ্ছাকৃতভাবে গিটে থাকে — ওটাই আসলে বিক্রির কপি। ক্লাসের তালিকা
দেখতে পাওয়াই কোর্স কেনার সবচেয়ে বড় যুক্তি, আর তাতে গোপন কিছু নেই।

`private.json` আর `course_notes/` গিটে **কখনো** যাবে না। রিপোজিটরি পাবলিক, আর
একটা unlisted ভিডিওর ID মানে পেইড রেকর্ডিং-এর খোলা দরজা।

যাচাই করার কমান্ড:

```bash
git grep -n "<যেকোনো ভিডিও ID>"        # কিছু আসা চলবে না
git status --short course_data          # private.json দেখা যাবে না
```

**এগুলো প্রোডাকশনে পৌঁছায় `vercel.json`-এর `includeFiles` দিয়ে**, গিট দিয়ে নয় —
ঠিক `book_pages_*/` যেভাবে যায়। এর মানে একটাই:

> ### ডিপ্লয় সবসময় ওয়ার্কিং কপি থেকে `vercel --prod`, কখনো `git push` নয়।

`includeFiles` কেবল সেই ফাইলগুলো বান্ডল করতে পারে যেগুলো ডিপ্লয়মেন্ট সোর্সে আছে,
আর গিট-ইন্টিগ্রেশন ডিপ্লয়ের সোর্স হলো রিপোজিটরি নিজেই। তাই push করে ডিপ্লয় করলে
ফাংশনটা যাবে খালি হাতে — প্রতিটা নোটে `404 not_found`, বিল্ড লগে একটা শব্দও নয়।
শেখার শিল্পের সাথে ঠিক এটাই হয়েছিল। `vercel.json`-এ master-এর git deploy বন্ধ করা
আছে যাতে ভুলেও সেটা না ঘটে।

একই কারণে **`.vercelignore`-এ `course_data/` বা `course_notes/` যোগ করা যাবে না**।
ওখানে কমেন্টে সেটা লেখা আছে।

আর উল্টো দিকের ফাঁদটাও মনে রাখতে হবে: **`vercel --prod` Firestore-এর rules
পাঠায় না।** `firestore.rules` রিপোতে থাকা মানে ওটা কার্যকর নয় — আলাদা করে
`npm run deploy:rules` চালাতে হয়। ক্লাসের মতামত ঠিক এই কারণেই একবার
`Missing or insufficient permissions` দিয়ে আটকেছিল: কোড, ছাঁচ, সবই ঠিক ছিল,
শুধু ফাইলটা কখনো Firebase-এ পৌঁছায়নি।

## `/api/course` চুক্তি

`api/membership.js`-এর হুবহু ছাঁচ: ID টোকেন Identity Toolkit-এ যাচাই হয়, তারপর
Firestore পড়া হয় **সেই ব্যবহারকারী হিসেবেই** — তাই কোনো service-account key লাগে
না। প্রতিটি `api/*.js` নিজের `verifyToken`/`getJSON` রাখে, ইচ্ছাকৃতভাবে
(`api/finance.js`-এর নোট দেখুন)।

| রিকোয়েস্ট | অথ | ফল | Cache-Control |
|---|---|---|---|
| `GET /api/course` | নেই | কোর্সের তালিকা | `public, max-age=300` |
| `?course=<id>` | ঐচ্ছিক | সিলেবাস + `access` | `private, no-store` |
| `?course&lesson=<n>` | লাগবে | `{host, video, notes}` | `private, no-store` |
| `?course&lesson&notes=html` | লাগবে | নোট, HTML | `private, no-store` |
| `?course&lesson&notes=pdf` | লাগবে | নোট, PDF (attachment) | `private, no-store` |

স্ট্যাটাস কোড:

- `400 bad_request` — ক্লাস নম্বর সংখ্যা নয়, বা অচেনা `notes` মান
- `401 login_required` — টোকেন নেই/জাল/মেয়াদোত্তীর্ণ
- `403 purchase_required` — টোকেন ঠিক, অ্যাক্সেস নেই (কোন প্রোডাক্ট কিনতে হবে, বডিতে আছে)
- `404 unknown_course` / `unknown_lesson` / **`not_found`** — শেষেরটা মানে catalog
  যে ফাইলের কথা বলছে সেটা ডিস্কে নেই: **প্রায় সবসময় `includeFiles` ফাঁদ**
- `501 course_data_not_configured` — `private.json` নেই বা পড়া যায়নি
- `503 lesson_not_ready` — ক্লাস আছে, কিন্তু ভিডিও ও নোট কোনোটাই এখনো যুক্ত হয়নি

সিলেবাস লগইন ছাড়াও পড়া যায় — সেটাই বিক্রি করে। কিন্তু ভিডিও ID ওখানে **কখনো**
যায় না, কে চাইল তাতে কিছু আসে যায় না।

## ইউটিউব সম্পর্কে সত্যি কথাটা

ইউটিউবে "ডোমেইন লক" বলে কিছু নেই। unlisted মানে ১১ অক্ষরের ID যার হাতে পড়বে,
সে-ই দেখতে পারবে — লগইন ছাড়াই, চিরকাল। `origin=` প্যারামিটার নিরাপত্তা দেয় না,
ওটা postMessage-এর জিনিস।

তাহলে এই ব্যবস্থায় লাভ কী:

1. **ID কোথাও পড়ে থাকে না** — `app.js`-এ নেই, গিটে নেই, ক্যাশে নেই, `localStorage`-এ
   নেই, DOM-এর `data-` অ্যাট্রিবিউটে নেই, URL-এ নেই। প্রতি ক্লাসে একটা অথেন্টিকেটেড
   রিকোয়েস্টে আসে আর একটা লোকাল ভেরিয়েবলে থাকে।
2. **ফাঁস হলে বাতিল করা যায়** — ভিডিও আবার আপলোড করুন, `private.json`-এ এক লাইন
   বদলান, redeploy। ফাঁস হওয়া ID মরে গেল। টেলিগ্রাম লিংকের বেলায় এটা করতে হলে
   প্রত্যেক সদস্যকে নতুন করে ইনভাইট করতে হতো।
3. **প্লেয়ারের ওপর ছাত্রের নিজের নাম ভাসে** — স্ক্রিন রেকর্ডিং ঠেকায় না, কিন্তু
   রেকর্ডিংটা কার অ্যাকাউন্ট থেকে এসেছে সেটা তার গায়ে লেখা থাকে। আসল প্রতিরোধ ওটাই।

DevTools খোলা একজন ছাত্র ID পড়তে পারবেন — এটা DRM নয়, আর সেভাবে বিক্রিও করবেন না।

**সত্যিকারের লক দরকার হলে** `private.json`-এর `host` ফিল্ডটাই সেই সেলাই। Bunny
Stream বা Cloudflare Stream-এ ভিডিও তুলে `host` বদলান, `api/course.js`-এ একটা
শাখা আর `createCourseYTPlayer`-এর পাশে আরেকটা প্লেয়ার যোগ করুন — বাকি ফিচারের
কিছুই বদলাতে হবে না।

## নতুন সেশন যোগ করার ধাপ

```bash
# ০. সেশনটা যদি শুধু অডিও হিসেবে থাকে (লাইভে স্ক্রিন রেকর্ড হয়নি), আগে mp4
#    বানিয়ে নিন — স্থির কভার + অডিও, ইউটিউবে তোলার মতো
node tools/make_session_videos.js --only 3

# ১. ইউটিউবে unlisted করে আপলোড করুন, ID কপি করুন

# ২. course_data/catalog.json — lessons[] এ নতুন সারি (আসল শিরোনাম, hasVideo: true)

# ৩. course_data/private.json — সেই নম্বরের নিচে "video": "<ID>"

# ৪. নোট — PDF দিলে সরাসরি বসে, HTML দিলে A4 PDF বানিয়ে নেয়
node tools/make_course_notes.js --course course-live --lesson 4 --from "…\session-04.pdf"
python tools/watermark_course_notes.py

# ৫. মিলিয়ে দেখুন — ভুল থাকলে non-zero exit
node tools/check_course_data.js

# ৬. ডিপ্লয়
vercel --prod
```

`make_course_notes.js` নিজেই `private.json`-এ নোটের পথ আর `catalog.json`-এ
`hasNotes` বসিয়ে দেয়, তাই ৪ নম্বর ধাপের পর হাতে কিছু লিখতে হয় না।

**প্রতিটা PDF অন্তত একবার চোখে খুলে দেখুন।** বাংলা যুক্তাক্ষর ভাঙা বা আরবি টোফু
হয়ে যাওয়া রেন্ডারিং-এর ভুল — কোনো স্ক্রিপ্ট ধরতে পারে না, ছাত্র প্রথম দিনেই ধরে।

স্ক্রিপ্ট চারটে যা ধরে:

- **`make_session_videos.js`** — অডিও-মাত্র সেশনকে ইউটিউবে তোলার মতো mp4 বানায়:
  একাধিক অংশ থাকলে জোড়া দেয় (দুটোই AAC হলে `-c copy`, রি-এনকোড নয়), সাইটের
  নিজের Hind Siliguri দিয়ে ১৯২০×১০৮০ কভার আঁকে headless Chrome-এ, আর
  `A:\course-uploads\`-এ mp4 + `UPLOAD.md` রেখে যায়। কভার Chrome-এ আঁকা হয়
  একই কারণে যে কারণে নোট — Pillow/ImageMagick বাংলা যুক্তাক্ষর শেপ করতে পারে না।

  থেমে যায় যদি: উৎস ফাইল না থাকে, অংশগুলোর ক্রম উল্টো মনে হয় (প্রতিটার শুরুর
  সময় = mtime − দৈর্ঘ্য দিয়ে যাচাই করা হয়), জোড়া দেওয়া বা তৈরি হওয়া ফাইলের
  দৈর্ঘ্য উৎসের যোগফলের সাথে না মেলে, বা কভারে লেখা বসেনি।

  ffmpeg PATH-এ নেই — স্ক্রিপ্ট মেশিনের যেটা আছে সেটাই খুঁজে নেয়। উধাও হয়ে গেলে
  `$env:FFMPEG` / `$env:FFPROBE` দিয়ে পথ দেখিয়ে দিন।

- **`make_course_notes.js`** — দুরকম উৎস নেয়:
  - **`.pdf`** → সরাসরি `course_notes/`-এ কপি হয়, রেন্ডার লাগে না (Chrome-ও লাগে
    না)। অ্যাপে নোট ট্যাবের **"📖 নোট পড়ুন"** সাইটের নিজের pdf.js রিডারেই খোলে —
    ফ্রি গাইডগুলো যেটাতে খোলে সেটাই, পাতা মনে রাখাসহ। বাইটগুলো টোকেন-যাচাই করা
    রিকোয়েস্টে এসে সরাসরি pdf.js-কে দেওয়া হয়, কোনো URL বা ক্যাশ তৈরি হয় না।
  - **`.html`** → headless Chrome-এ A4 PDF বানায়, সাথে অ্যাপে পড়ার একটা HTML
    সংস্করণও (srcdoc iframe-এ বসে, রিফ্লো হয়, নিজের ডার্ক মোড রাখে)।

  থেমে যায় যদি: PDF-এ লেখা হারিয়ে যায় (পাতা কমে যায়), ফাইল ৪০ KB-র কম, বা রেন্ডার
  করা পাতায় প্রায় কোনো লেখা নেই। পাতা *বেড়ে* গেলে শুধু সতর্ক করে — লেখা আছে, শুধু
  ডিজাইনার যেখানে পাতা ভাঙতে চেয়েছিলেন সেখানে ভাঙেনি।
- **`watermark_course_notes.py`** — `tools/watermark_pdfs.py`-র ছাপ ও এনক্রিপশন
  হুবহু বসায় (কনটেন্ট-স্ট্রিমে টাইল করা ওয়াটারমার্ক + AES-256; কপি ও এডিট বন্ধ,
  প্রিন্ট ও স্ক্রিন-রিডার খোলা)। sha256 ম্যানিফেস্ট রাখে যাতে একই ফাইলে দুবার ছাপ
  না পড়ে।
- **`check_course_data.js`** — catalog বলছে ভিডিও/নোট আছে কিন্তু নেই, নোটের ফাইল
  ডিস্কে নেই, নম্বর দুবার, module অচেনা, বা শিরোনাম এখনো "নমুনা —" দিয়ে শুরু।

## অগ্রগতি কোথায় জমা হয়

`users/<uid>.courseProgress = { "course-live": { "3": { sec, done, at } } }`

আলাদা কালেকশন বানানো হয়নি, কারণ `users/{uid}` ইতিমধ্যে নিজের জন্য লেখা যায়
(`memberships` ছাড়া) — মানে **`firestore.rules` বদলাতে হয়নি**, নতুন করে কিছু
খুলতেও হয়নি। ডকুমেন্টটা `watchUnlocks()`-এর `onSnapshot`-এ আগে থেকেই আছে, তাই
অন্য ডিভাইসের অগ্রগতি বিনা খরচে চলে আসে। ২৭ ক্লাসে ~১.৬ KB, সীমা ১ MiB।

অগ্রগতি অ্যাক্সেস নয়, তাই কেউ নিজেরটা এডিট করলে ক্ষতি নেই।

**থ্রটলটা ইচ্ছাকৃত ও জরুরি।** localStorage-এ প্রতি ৫ সেকেন্ডে লেখা হয়, Firestore-এ
শুধু pause / শেষ / ক্লাস বদল / ওভারলে বন্ধের সময়, আর তাও ৩০ সেকেন্ডে একবারের বেশি
নয়। প্রতি ৫ সেকেন্ডে Firestore-এ লিখলে ওই `onSnapshot` মিনিটে বারো বার
`applyPersonalization()` চালাত — গোটা হোম স্ক্রিন বারো বার নতুন করে আঁকা, এমন একটা
সংখ্যার জন্য যেটা কেউ তাকিয়ে দেখছে না। রিমোট আর লোকাল মেলানো হয় `max(sec)` দিয়ে,
যাতে চলতি ক্লাসের মাঝে একটা snapshot এসে পেছনে টেনে না নেয়।

## ক্লাসের মতামত

বিদ্যমান রিভিউ ব্যবস্থাই ব্যবহার হয়, target id `course-live-c3` ছাঁচে।

**হাইফেন ছাড়া আর কিছু নয়** — `firestore.rules` রিভিউয়ের ডকুমেন্ট id পড়ে
`<uid>_<target>` হিসেবে, তাই target-এ একটা আন্ডারস্কোর থাকলে ভাগটা ভুল জায়গায়
হতো আর লেখাটাই আটকে যেত।

বইয়ের মতোই মালিকানা-গেট: কোর্সে যুক্ত না থাকলে ক্লাসের মতামত দেওয়া যায় না।

⚠ ল্যান্ডিং পেজে সর্বশেষ ৬টা রিভিউ বিল্ড-টাইমে বসে (`tools/export_reviews.js` →
`reviews.json` → `injectReviews()`)। ক্লাস-রিভিউ বাড়লে সেগুলো প্রোডাক্টের
টেস্টিমোনিয়াল ঠেলে সরিয়ে দিতে পারে। তখন `export_reviews.js`-এ prefix ধরে একটা
সীমা বসাতে হবে — এখনো বসানো হয়নি, কারণ এখনো একটাও ক্লাস-রিভিউ নেই।

## কোথায় কী আছে

| ফাইল | ভূমিকা |
|---|---|
| `api/course.js` | পুরো গেট — টোকেন, অ্যাক্সেস, ভিডিও ID, নোটের বাইট |
| `course_data/catalog.json` | ক্লাসের তালিকা (ট্র্যাকড) |
| `course_data/private.json` | ভিডিও ID + নোটের পথ (gitignored) |
| `course_notes/` | নোটের বাইট (gitignored) |
| `app.js` → `#web-only` কোর্স ব্লক | তাক, ওভারলে, প্লেয়ার, নোট, অগ্রগতি |
| `styles/07-course.css` | কোর্স এরিয়ার সব CSS (`/* #web-only */`) |
| `index.html` → `#my-courses-section`, `#course-view` | দুটো সারফেস |
| `tools/make_course_notes.js` | HTML → অ্যাপের নোট + A4 PDF |
| `tools/watermark_course_notes.py` | ছাপ ও এনক্রিপশন |
| `tools/check_course_data.js` | ডিপ্লয়ের আগের গেট |
| `tools/smoke-course.js` | নকল API দিয়ে পুরো ফ্লো চালিয়ে দেখা (`npm run smoke`-এ আছে) |

পুরো ফিচারটা `#web-only` মার্কারের ভেতরে। APK কিছু বিক্রি করে না, আর কোর্সের কোড
ওখানে পাঠানো মানে Play লিস্টিং-এর ভেতরে একটা দামওয়ালা পণ্য ঢুকিয়ে দেওয়া —
`tools/audit-native.js` সেটাই পাহারা দেয়।

`npm run check` চালালে দুই বিল্ড, অডিট আর তিনটে smoke একসাথে চলে:

- `smoke.js public` — সারফেস দুটো আছে, বন্ধ অবস্থায় শুরু হয়, আর বিল্ড-করা পেজে
  কোনো ইউটিউব ID বা গোপন ফাইলের নাম নেই;
- `smoke.js native` — APK-তে কোর্সের কিছুই নেই;
- `smoke-course.js` — নকল `/api/course` দিয়ে গোটা ফ্লো চালায়: তাক → সিলেবাস →
  ক্লাস → নোট → মতামত → অগ্রগতি, আর মেয়াদ ফুরালে ও সার্ভার `403` দিলে কী দেখায়।

আর ডিপ্লয়ের ঠিক আগে `node tools/check_course_data.js` — ওটা `npm run check`-এ
নেই, কারণ ওটা কোডের নয়, কনটেন্টের পরীক্ষা।

## এখনো যা বাকি

- **ভিডিও।** এখনো একটাও সেশনের ID `private.json`-এ বসানো হয়নি, নোটও নেই। যতক্ষণ
  তা না হয়, "আমার কোর্স" তাকটা কারও চোখেই পড়বে না — খালি কোর্স দেখানো হয় না,
  কারণ চুপচাপ ঘাটতির চেয়ে দৃশ্যমান ঘাটতি খারাপ।
- **catalog-এ এখনো নমুনা সারি।** তিনটে "নমুনা —" শিরোনাম বসানো আছে শুধু পাইপলাইন
  পরীক্ষার জন্য; `check_course_data.js` সেগুলো নিয়ে ডিপ্লয় করতে দেবে না।
- **ফোন + পাসওয়ার্ড লগইন নেই এবং Firebase-এ হয়ও না** — ফোনে শুধু SMS OTP হয়।
  এখন চালু আছে ইমেইল+পাসওয়ার্ড আর Google। দুটো পথ খোলা: (ক) OTP চালু করা
  (`firebase-config.js`-এ `PHONE_LOGIN_ENABLED`, স্ক্যাফোল্ড আগে থেকেই আছে), বা
  (খ) `01XXXXXXXXX@phone.alquranicruqyahhealing.com` ছাঁচে সিন্থেটিক ইমেইল — নতুন
  কোনো সিক্রেট লাগে না, কিন্তু SMS দিয়ে পাসওয়ার্ড রিসেট করা যায় না। আলাদা সিদ্ধান্ত।
