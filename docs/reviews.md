# রিভিউ ও রেটিং

মানুষ বই, কোর্স, রুকইয়াহ সেবা আর সাইট — সবকিছু নিয়ে মতামত দিতে পারেন, আর সেই
মতামত সবার সামনে দেখানো হয়।

## কে দিতে পারবেন

| কী নিয়ে | কে |
|---|---|
| বই | **যিনি কিনেছেন কেবল তিনি** — স্টোর কার্ডে যে স্কোর বসছে সেটা সত্যিকারের পাঠকের হতে হবে |
| কোর্স / লাইভ ক্লাস | যিনি কিনেছেন |
| রুকইয়াহ সেবা · ওয়েবসাইট ও অ্যাপ | **লগইন করা যেকেউ** |

লাইভ ক্লাসের সদস্য বা রোগীরা কারো `courses` অ্যারেতে আলাদা করে থাকেন না, তাই
আগের ব্যবস্থায় তাঁদের কিছু বলার উপায়ই ছিল না — অথচ তাঁরাই সবচেয়ে ভালো বলতে
পারেন। তাই সাধারণ টার্গেট দুটো খোলা।

**লগইন বাধ্যতামূলক** — এই কোডবেসে কোনো captcha, rate limit বা হানিপট নেই, তাই
অ্যাকাউন্টই একমাত্র বাধা। একজন এক জিনিসে একটাই রিভিউ দিতে পারেন (ডক-আইডি
`uid_target`), আর লেখার সীমা ১২০০ অক্ষর।

## প্রকাশ সঙ্গে সঙ্গে — তাই মুছে ফেলার বোতাম

জমা দেওয়ামাত্র রিভিউ সবার সামনে চলে যায়, আগে কোনো অনুমোদন লাগে না। ফলে কেউ
আপত্তিকর কিছু লিখলে একমাত্র প্রতিকার হলো পরে মুছে ফেলা — অ্যাডমিন প্যানেল →
**⭐ Reviews** → প্রতিটি রিভিউর নিচে **🗑 মুছে ফেলুন**।

`improve` ("কীভাবে আরও ভালো করা যায়") ফিল্ডটি **প্রকাশ্য নয়** — কেবল অ্যাডমিন
প্যানেলে দেখা যায়। মডালেও সেটা লেখা আছে।

## Firestore নিয়ম (বাধ্যতামূলক)

Firebase Console → **Firestore Database** → **Rules**। বিদ্যমান নিয়মের ভেতরে
এটা যোগ করুন:

```
match /reviews/{id} {
  // যে কেউ পড়তে পারবে — লগইন না করেও। রিভিউ দেখতে অ্যাকাউন্ট লাগার কথা নয়,
  // আর ল্যান্ডিং পেজের টেস্টিমোনিয়ালও এখান থেকেই আসে।
  allow read: if true;

  // লিখতে পারবেন কেবল লগইন করা ব্যক্তি, আর কেবল নিজের নামের ডকে:
  // ডক-আইডি হলো uid_target, তাই অন্যের নামে রিভিউ লেখা যাবে না এবং
  // একজন একই জিনিসে একাধিক রেটিং জমাতে পারবেন না।
  allow create, update: if request.auth != null
                        && id.split('_')[0] == request.auth.uid
                        && request.resource.data.uid == request.auth.uid
                        && request.resource.data.rating is int
                        && request.resource.data.rating >= 1
                        && request.resource.data.rating <= 5;

  // মুছতে পারবেন শুধু অ্যাডমিন।
  allow delete: if request.auth != null
                && request.auth.token.email == 'crackdmcbuet@gmail.com';
}
```

**এটা না দিলে কী হয়:** `loadAllReviews()` চুপচাপ ব্যর্থ হয় (কনসোলে
`Review load error: Missing or insufficient permissions`), কার্ডে কোনো তারকা
আসে না, রিভিউ ওয়াল খালি থাকে, আর রিভিউ জমা দিতে গেলে "সংরক্ষণ করা গেল না"
দেখায়। ফিচারটা থাকা আর না-থাকা তখন একই কথা — বহুদিন ঠিক এই অবস্থাতেই ছিল।

> `id.split('_')[0]` কাজ করে কারণ uid-তে আন্ডারস্কোর থাকে না (Firebase uid
> শুধু অক্ষর ও অঙ্ক)। target-এ হাইফেন থাকে, আন্ডারস্কোর নয় — `live-class`,
> `yasin-karishma`, `ruqyah-service`।

## যাচাই

নিয়ম বসানোর পর, লগআউট অবস্থায় ব্রাউজারে:

```
https://firestore.googleapis.com/v1/projects/al-quranic-ruqyah/databases/(default)/documents/reviews
```

তালিকা দেখালে read খোলা আছে। তারপর অ্যাপে লগইন করে একটা রিভিউ দিন — কার্ডে
তারকা ও হোম পাতার "💬 সবার মতামত" অংশে লেখাটা সাথে সাথে আসবে।

## ল্যান্ডিং পেজের টেস্টিমোনিয়াল

ওয়েবসাইটের প্রথম পাতা Firestore-এ কোনো কল করে না। বিল্ডের সময়
`tools/export_reviews.js` রিভিউগুলো টেনে `reviews.json`-এ রাখে (রিপোতে কমিট করা),
আর `build.js` সেখান থেকে **HTML-এর ভেতরেই** লেখাগুলো বসিয়ে দেয়। কারণ:

- ল্যান্ডিং পেজে Firebase SDK লোড করতে হয় না (~৩০০ KB বাঁচে)
- সার্চ ইঞ্জিন লেখাগুলো সরাসরি পায়, JS চালানোর অপেক্ষা করতে হয় না
- `aggregateRating` structured data একই সংখ্যা থেকে বসে

`landing.html`-এ দুটি প্লেসহোল্ডার আছে যা বিল্ড ভরে দেয়:

| প্লেসহোল্ডার | কী বসে |
|---|---|
| `<!--REVIEWS_SECTION-->` | "তাঁরা যা বলেছেন" অংশ, সর্বোচ্চ ৬টি রিভিউ (রিভিউ না থাকলে **কিছুই না** — খালি হেডিং ক্ষতি করে) |
| `"aggregateRating":"@@RATING:<target>@@"` | ঐ পণ্যের গড় ও সংখ্যা (রিভিউ না থাকলে প্রপার্টিটাই মুছে যায়) |

**গুগলে যে রেটিং দেখাবে, পাতায় সেই রিভিউ দেখা যেতেই হবে** — না থাকলে markup
বসানো হয় না। বানানো রেটিং একই সাথে মিথ্যা এবং ম্যানুয়াল অ্যাকশনের আমন্ত্রণ।

ফলে ল্যান্ডিং পেজের রিভিউ **পরের ডিপ্লয়ে হালনাগাদ হয়**, সঙ্গে সঙ্গে নয়।
অ্যাপে (`/app`) সবসময় লাইভ। এই পার্থক্যটা ইচ্ছাকৃত: অ্যাপ যাঁরা ইতিমধ্যে
এসেছেন তাঁদের জন্য, ল্যান্ডিং পেজ যাঁরা এখনো সিদ্ধান্ত নেননি তাঁদের জন্য।

Firestore অগম্য হলে (নিয়ম বসানো হয়নি, নেট নেই) বিল্ড **ফেল করে না** — শেষবার
কমিট করা `reviews.json` ব্যবহার হয় এবং বিল্ড লগে কারণটা লেখা থাকে।
`improve` ফিল্ডটি এই ফাইলে **কখনো যায় না** — ওটা প্রকাশ্য নয়।
