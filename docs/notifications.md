# নোটিশ ও অফার পাঠানো — সেটআপ ও ব্যবহার

অ্যাডমিন এখন অ্যাপের ভেতর থেকেই সব ব্যবহারকারীকে নোটিশ বা অফার পাঠাতে পারেন।

## কীভাবে কাজ করে

দুটো আলাদা পথ, দুটোই দরকার:

| পথ | কী করে | না থাকলে |
|---|---|---|
| **Firestore `announcements`** | নোটিশটা জমা থাকে। অ্যাপ খুললেই 🔔 আইকনে দেখা যায়। | কিছুই থাকে না |
| **FCM পুশ** | অ্যাপ বন্ধ থাকলেও ফোনে নোটিফিকেশন আসে। | নোটিশ থাকে, শুধু সাথে সাথে জানায় না |

**গুরুত্বপূর্ণ:** Firestore-এ লেখা হয় **আগে**, পুশ যায় **পরে**। পুশ ব্যর্থ হলেও নোটিশটা প্রকাশিত হয়ে যায় — উল্টোটা হলে পুশ এমন কিছুর দিকে ইশারা করত যা নেই।

পুশ যায় **টপিক `all`**-এ, প্রতিটি ডিভাইসের আলাদা টোকেন সংরক্ষণ করে নয়। ফলে কোনো টোকেন-টেবিল নেই, ফোন মুছে ফেললে পরিষ্কার করার কিছু নেই, আর কার কাছে অ্যাপ আছে তার কোনো তালিকাও কোথাও নেই। বিনিময়ে একজনকে আলাদা করে পাঠানো যায় না — যা এখানে সমস্যা নয়, কারণ যা পাঠানো হচ্ছে তা সবার জন্য।

## ধাপ ১ — Firestore নিয়ম (বাধ্যতামূলক)

Firebase Console → **Firestore Database** → **Rules**। বিদ্যমান নিয়মের ভেতরে এটা যোগ করুন:

```
match /announcements/{id} {
  // যে কেউ পড়তে পারবে — লগইন না করেও। নোটিশ দেখতে অ্যাকাউন্ট লাগার কথা নয়।
  allow read: if true;
  // শুধু অ্যাডমিন লিখতে বা মুছতে পারবেন।
  allow write: if request.auth != null
               && request.auth.token.email == 'crackdmcbuet@gmail.com';
}
```

এটা ছাড়া নোটিশ পাঠালে "সেভ হয়নি: Missing or insufficient permissions" দেখাবে।

## ধাপ ২ — পুশের জন্য সার্ভিস অ্যাকাউন্ট

পুশ পাঠাতে সার্ভারের একটা চাবি লাগে। এটা না দিলে নোটিশ প্রকাশিত হবে, শুধু ফোনে পুশ যাবে না — অ্যাডমিন প্যানেলে পরিষ্কার করে সেটা লেখা থাকবে।

1. Firebase Console → ⚙️ **Project settings** → **Service accounts**
2. **Generate new private key** → একটা `.json` ফাইল নামবে
3. Vercel → প্রজেক্ট → **Settings** → **Environment Variables**
   - Name: `FIREBASE_SERVICE_ACCOUNT`
   - Value: **ওই ফাইলের পুরো লেখাটা** (কপি-পেস্ট, পুরোটাই)
   - Environment: Production
4. Redeploy

> ⚠️ ওই JSON ফাইলটা পুরো প্রজেক্টের চাবি। এটা **Vercel ড্যাশবোর্ড ছাড়া আর কোথাও নয়** — কোনোভাবেই এই রিপোজিটরিতে নয়, কারণ রিপোজিটরিটা পাবলিক।

## ধাপ ৩ — Cloud Messaging চালু আছে কিনা

Firebase Console → **Project settings** → **Cloud Messaging** → **Firebase Cloud Messaging API (V1)** — **Enabled** থাকতে হবে। না থাকলে ⋮ মেনু থেকে চালু করুন।

`google-services.json` অ্যাপে থাকতে হবে (Google সাইন-ইনের জন্য যেটা এমনিতেই লাগছে — `docs/firebase-android.md`)। ওটা ছাড়া অ্যাপ পুশের জন্য রেজিস্টারই করতে পারে না।

## পাঠানোর নিয়ম

1. অ্যাপে অ্যাডমিন অ্যাকাউন্টে লগইন → 👨‍⚕️ FAB → **🔔 নোটিশ**
2. শিরোনাম ও বিবরণ লিখুন
3. ধরন বাছুন — 📢 নোটিশ বা 🎁 অফার (অফার হলুদ দাগে আলাদা দেখায়)
4. চাইলে একটা লিংক দিন
5. **সবার কাছে পাঠান**

নিচে অবস্থা লেখা থাকবে — নোটিশ প্রকাশিত হয়েছে কিনা, আর পুশ গেছে কিনা, আলাদা করে।

### খেয়াল রাখবেন

- **পুশ ফেরানো যায় না।** নোটিশ মুছলে অ্যাপের ভেতর থেকে সরে যায়, কিন্তু যাদের ফোনে নোটিফিকেশন পৌঁছে গেছে তাদের কাছ থেকে ওটা তুলে নেওয়ার কোনো উপায় নেই।
- **শিরোনাম ১০০ অক্ষর, বিবরণ ২৪০ অক্ষরের বেশি নোটিফিকেশনে দেখাবে না** — বাকিটা অ্যাপের ভেতরে পুরোটাই থাকবে।
- **বেশি পাঠাবেন না।** নোটিফিকেশন বন্ধ করে দেওয়ার সবচেয়ে বড় কারণ এটাই, আর একবার বন্ধ করলে আর কখনো খোলে না।

## অ্যাপে ব্যবহারকারী যা দেখেন

হেডারের 🔔 আইকনে না-পড়া নোটিশের সংখ্যা লাল বৃত্তে দেখায়। ট্যাপ করলে সব নোটিশের তালিকা — নতুনগুলো সবুজ দাগে, অফার হলুদ দাগে। নোটিফিকেশন পারমিশন না দিয়ে থাকলে তালিকার উপরে চালু করার প্রস্তাব থাকে।

প্রথমবার অ্যাপ ইনস্টল করলে পুরোনো নোটিশগুলো "না-পড়া" হিসেবে গোনা হয় না — নইলে অ্যাপ খুলেই কয়েক মাসের পুরোনো অফার ঘোষণা করত।
