# অ্যাডমিন হিসাব ট্যাব (💰) — সেটআপ

মালিকের নিজের **bKash / Nagad / Rocket / ব্যাংক** লেনদেন একটা প্রাইভেট Google
Sheet-এ জমা হয় (আলাদা প্রজেক্ট: `C:\Users\faisa\mfs-tracker\`), আর সেটাই
`/app`-এর অ্যাডমিন মোডালের ৫ম ট্যাবে দেখা যায়।

```
ব্রাউজার (admin হিসেবে Google সাইন-ইন)
   │  currentUser.getIdToken()
   ▼  GET /api/finance?path=dash&month=…    Authorization: Bearer <id token>
api/finance.js — verifyAdmin() → Identity Toolkit
   │    টোকেন নেই/ভুল      → 401 login_required
   │    ইমেইল ≠ ADMIN_EMAIL → 403 admin_only      ← আসল সীমানা
   ▼  সার্ভার-টু-সার্ভার: GET <SHEET_API_URL>?token=<SHEET_API_TOKEN>&…
Apps Script doGet → JSON → ব্রাউজার (Cache-Control: private, no-store)
```

## ⚠ যে কথাটা ভুল বোঝা সবচেয়ে সহজ

`app.js`-এর ক্লায়েন্ট-সাইড চেকগুলো — FAB লুকানো (`app.js:984`),
`openAdminDashboard()`-এর ইমেইল তুলনা (`app.js:2896`), প্যানের `hidden` ক্লাস —
**নিছক প্রসাধনী**। যে কেউ devtools খুলে `openAdminDashboard()` ডেকে প্যান
দেখিয়ে ট্যাবে ক্লিক করতে পারে। সে খালি ড্যাশবোর্ড আর `403 admin_only` দেখবে।

**ইন্টারনেট আর খতিয়ানের মাঝে একমাত্র বাধা `api/finance.js`-এর `verifyAdmin()`।**
এই ফিচারের প্রতিটি রিভিউয়ে ক্লায়েন্টকে অবিশ্বস্ত অলংকার হিসেবেই দেখতে হবে।

## env var (Vercel ড্যাশবোর্ড, আর কোথাও নয়)

| নাম | মান |
|---|---|
| `SHEET_API_URL` | `https://script.google.com/macros/s/AKfy…/exec` |
| `SHEET_API_TOKEN` | Apps Script-এর **`READ_TOKEN`** |

**⚠ `READ_TOKEN`, `INGEST_TOKEN` নয়।** দুটো আলাদা টোকেন রাখার পুরো কারণটাই
এই: read টোকেন query string-এ যায় (তাই Google-এর সার্ভার-লগে ওঠে) আর Vercel-এ
বসে থাকে; সেটা ফাঁস হলেও **ভুয়া লেনদেন ঢোকানো যাবে না**, কারণ লেখার জন্য
ingest টোকেন লাগে।

ধাপ:

1. `mfs-tracker` Apps Script ডিপ্লয় করো (তার `README.md` দেখো), আর
   `setSecrets()` চালিয়ে `READ_TOKEN` নাও।
2. Vercel → Project → Settings → Environment Variables — **Production ও Preview
   দুটোতেই** উপরের দুটো বসাও। (Preview-তে না দিলে preview deploy `501` দেবে আর
   তুমি ভুতুড়ে সমস্যা খুঁজতে থাকবে।)
3. Redeploy।

এই দুটো মান **এই রিপোজিটরিতে কখনো নয় — রিপো পাবলিক।**

## সেট করার আগেও ট্যাবটা শিপ করা যায়

env var না থাকলে ফাংশন `501 finance_not_configured` দেয়, আর ট্যাব স্পিনার নয়
বরং একটা বাক্য দেখায়: *"⚠️ হিসাব এখনো সেট করা হয়নি…"*। তাই Sheet তৈরির আগেই
ফ্রন্টএন্ড ডিপ্লয় করা নিরাপদ।

## স্টেটাস কোড → ব্যবহারকারী যা দেখবে

| কোড | অর্থ |
|---|---|
| `401 login_required` | সাইন-ইন করা নেই বা টোকেন মেয়াদোত্তীর্ণ |
| `403 admin_only` | টোকেন বৈধ, কিন্তু ইমেইল অ্যাডমিন নয় |
| `501 finance_not_configured` | env var বসানো হয়নি |
| `502 sheet_unreachable` / `sheet_bad_response` / `sheet_refused` | Apps Script-এ সমস্যা |
| `504 sheet_timeout` | Sheet ৮ সেকেন্ডে উত্তর দেয়নি |
| `429 too_many_requests` | প্রতি মিনিটে ৩০-এর বেশি (per-instance রেলিং) |

`sheet_bad_response` কাল্পনিক নয়: Apps Script-এর `doGet` throw করলে সে **200
সহ একটা HTML error page** দেয়, আর `JSON.parse` ফেটে যায়। ফাংশন সেটা ধরে,
সার্ভার-লগে প্রথম ২০০ অক্ষর ছাপে, কিন্তু ব্রাউজারে শুধু কোড পাঠায় — ওই HTML-এ
স্ক্রিপ্ট URL থাকতে পারে।

## APK-তে যাবে না — কেন, আর কী পাহারা দেয়

কারণ **গোপনীয়তা**: ব্যক্তিগত আর্থিক ডেটার শিপ করা অ্যাপ-বান্ডলে কোনো কাজ নেই,
গেট থাকুক বা না থাকুক। পাশাপাশি পলিসি-ঝুঁকিও আছে, কারণ UI-তে `৳`, `bKash`,
`Nagad`, `Rocket` — ঠিক সেই শব্দভাণ্ডারই ব্যবহৃত হয় যা রিভিউয়ার grep করে।

| স্তর | কোথায় | কেন ওখানে |
|---|---|---|
| HTML | `index.html`-এ ২টি `<!-- #web-only -->` অঞ্চল | `build.js` HTML-এ মার্কার-balance যাচাই করে, লাইন নম্বর দিয়ে ফেল করে |
| JS | **`app.js`-এর একদম শেষে** | JS মার্কার **যাচাই হয় না**; শেষে থাকলে ক্লোজ ভুল হলে regex কিছুই ম্যাচ করে না → ব্লক APK-তে যায় → অডিট ধরে। **নীরবের বদলে সরব** |
| CSS | **`styles/06-chat-shell.css`-এর শেষে** | স্টাইলশিট `01`→`06` জোড়া দিয়ে *তারপর* স্ট্রিপ হয়, তাই এক ফাইলের ওপেন মার্কার পরের ফাইলের ক্লোজ ম্যাচ করতে পারে; `06` সর্বশেষ |

তিনটে পাহারা, আর **তিনটেই সত্যিই পরীক্ষা করা হয়েছে**:

1. `tools/audit-native.js`-এ `FORBIDDEN_ANYWHERE` needle **`fin-balgrid`** ও
   **`/api/finance`**। ⚠ পেন-আইডি (`admin-finance-pane`) ইচ্ছাকৃতভাবে needle
   **নয়** — `switchAdminView()` শেয়ার্ড কোড, APK-তে যায়, আর ওখানে ওই আইডি
   বৈধভাবেই আছে (নেটিভে অনুপস্থিত একটা প্যান লুকানোর জন্য)।
2. মার্কআপে রাখা **উদ্দেশ্যমূলক `৳`** (`fin-hint`)। `audit-native.js:50`-এর
   `PURCHASE_LANGUAGE`-এ `৳` আছে আর শিপ করা `.html`-এ পেলে হার্ড ফেল — তাই
   ভবিষ্যতে কেউ মার্কার ফেলে দিলে **বিনা নতুন কোডে** ধরা পড়ে।
3. `tools/smoke.js`-এ ৬টি অ্যাসারশন — নেটিভে প্যান ও `loadFinance` **অনুপস্থিত**;
   ওয়েবে প্যান উপস্থিত, শুরুতে `hidden`, ৫টা ট্যাব, `loadFinance` সংজ্ঞায়িত।

যাচাইয়ের ফলাফল: **একটা মার্কার মুছলে** বিল্ড ফেল করে
(`❌ index.html:1288 — closing #web-only marker with nothing open.`);
**দুটোই মুছলে** বিল্ড পাস করে কিন্তু অডিট ৩টা ব্যর্থতা দেয় (`fin-balgrid` +
দুটো `৳`)। অর্থাৎ দুই ধরনের ভুলই ধরা পড়ে।

## service worker

`CACHE_NAME` → `ruqyah-pro-v13`। `SHELL`-এ কিছু যোগ করার নেই (`/app.html` ও
`/app.js` আগেই আছে, আর এই ফিচার শুধু ওই দুটোই বদলায়)। `/api/finance` ইতিমধ্যেই
ক্যাশ থেকে বাদ — `service-worker.js`-এ `if (/\/api\//.test(url)) return;`।

`build.js` ও `vercel.json`-এ **কোনো পরিবর্তন লাগেনি** (নতুন পেজ নেই, নতুন
স্টাইলশিট ফাইল নেই — এ কারণেই CSS নতুন `07-*.css`-এ না রেখে `06`-এর শেষে
বসানো হয়েছে; নতুন ফাইল মানে নতুন `<link>`, আর `inlineStyles` তালিকা-অমিলে
বিল্ড ফেল করে)।

## XSS — ঐচ্ছিক নয়

counterparty-র নাম আসে **SMS বডি** থেকে। অর্থাৎ **যে কেউ এই ফোনে টেক্সট
পাঠিয়ে** অ্যাডমিন সেশনে (সাইটের সর্বোচ্চ-ক্ষমতার সেশন — Firestore লেখে,
purchase কনফার্ম করে, সব ইনস্টলে push পাঠায়) মার্কআপ ঢোকানোর চেষ্টা করতে পারে।
তাই `innerHTML`-এ যাওয়া **প্রতিটি** ফিল্ড `esc()` দিয়ে যায়, আর Apps Script-এও
ingest-এ derived ফিল্ড থেকে `<>&"'` ছেঁটে দেওয়া হয় (দ্বিতীয় স্তর)।
API কখনো `raw_text` ব্রাউজারে পাঠায় না।

## জানা ও গৃহীত ঝুঁকি

- **ব্যবসায়িক ডোমেইনের পেছনে ব্যক্তিগত আর্থিক ডেটা।** ডোমেইন বিক্রি/হস্তান্তর
  হলে, বা DNS/Vercel অ্যাকাউন্ট আপস হলে হিসাবও সঙ্গে যায়। পেশেন্ট ডেটা
  ইতিমধ্যেই ওই পৃষ্ঠে থাকায় এটা **পূর্ব-নজিরযুক্ত, নিরাপদ নয়**। একমাত্র
  কাঠামোগত সমাধান আলাদা origin। সান্ত্বনা: **পরে সরানো সস্তা**, কারণ ডিজাইনটাই
  প্রক্সি + একটা ট্যাব — `api/finance.js` আর web-only অঞ্চলগুলো সরালেই হয়।
- **Firebase ID টোকেন ফাঁস হলে ~১ ঘণ্টা পূর্ণ read।** bearer টোকেন,
  proof-of-possession নেই, expiry ছাড়া revocation নেই (অ্যাকাউন্ট ডিজেবল করলে
  *refresh* থামে, চলতি টোকেন নয়)। ওই টোকেন ইতিমধ্যেই `/api/push` ও `/api/book`
  দেয়, তাই এটা বিদ্যমান blast radius বাড়ায়, নতুন তৈরি করে না।
- **`/api/finance` প্রকাশ্যে আবিষ্কারযোগ্য, আর সেটা ঠিক করা যায় না।** যেকোনো
  serverless রুটের জন্যই তাই (`/api/push`-ও একই)। অস্পষ্ট পাথে লুকানো হয়নি —
  তাতে grep-যোগ্যতা হারিয়ে কোনো আসল সুরক্ষা মিলত না। `X-Robots-Tag: noindex` আছে।
- **per-instance রেট লিমিট আসল রেট লিমিট নয়** — Vercel একাধিক instance চালাতে
  পারে। এটা runaway ক্লায়েন্টের বিরুদ্ধে রেলিং, নিরাপত্তা-নিয়ন্ত্রণ নয়;
  কোডের কমেন্টেও সেটাই লেখা।
- **নীরব বাসিত্বই সবচেয়ে সম্ভাব্য বাস্তব ব্যর্থতা** — নিরাপত্তা নয়,
  ডেটা-বিশ্বস্ততার ঝুঁকি। তাই health নির্দেশক সবার উপরে, **সুস্থ থাকলেও দেখায়**
  (যে নির্দেশক শুধু ভাঙলে আসে, তার অনুপস্থিতিকে বিশ্বাস করা যায় না), আর
  **`health` একদমই না এলে লাল** — Apps Script নিজে ডাউন থাকলে তখন "ঠিক আছে"
  দেখানোই সবচেয়ে বিপজ্জনক।
